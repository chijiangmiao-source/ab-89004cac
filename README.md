# 隔离控制协议迁移裁决台

维护工程师在隔离控制协议升级时，用本服务确认正在执行的会话能安全迁入新规程。
裁决不是比较起始状态，而是从每个会话的**当前状态**计算旧/新两个确定有限状态
规程之间的**最大双向匹配关系（互模拟）**：

- 两侧的可见输出必须相同；
- 允许动作集合必须相同（任一可达同名动作两侧都须存在，防止下一条动作
  放大设备权限）；
- 每个同名动作的后继状态对仍须在匹配关系中（不动点）。

候选迁移仅当**全部冻结会话**都可映射时才允许发布。阻断会话返回从锚点到首个
具体失配对的**最短阻断路径**与原因（如输出不同、动作缺失、后继不匹配）。

## 页面

录入旧规程、新规程（JSON：状态 → 可见输出 + 允许动作及迁移）和至多 12 个当前
会话，填写稳定迁移标识后：

1. **冻结并裁决**：显示每个会话的目标状态与映射证据，或首个阻断路径；
2. **发布迁移**：仅全部会话可映射时可点；
3. **查询标识**：按迁移标识取回持久裁决。

页头实时显示健康状态（`/healthz`）。

## 持久化与并发语义

一次冻结把以下内容绑定进**同一条持久裁决**（SQLite，WAL + 全量同步）：

- 旧/新规程摘要（SHA-256）与规格；
- 会话快照及其版本摘要；
- 逐会话映射证据；
- 阶段：`FROZEN → PUBLISHED`。

- 迁移标识是幂等键：**同标识 + 同快照**重传返回原裁决；
- 同标识但规程或会话快照不同（两个页面竞争、陈旧页面重传）→ `409`，
  两份会话快照永不混用；
- 发布是单条条件 `UPDATE … WHERE phase='FROZEN'`，并发发布只有一个赢家，
  结论唯一且重传幂等；
- 冻结后或切换前模拟中断（直接杀进程）并重开：只能恢复为**未发布的 FROZEN**
  或**唯一已发布的 PUBLISHED** 结论。

## 运行

```bash
# 宿主端口可配置
HOST_PORT=9090 docker compose up --build
# 打开 http://localhost:9090
```

## 验收（Compose verify 服务）

```bash
docker compose --profile verify run --rm verify
```

依次执行并以退出码报告（全绿退出 0）：

1. 规则测试：可迁移、动作缺失、输出不同、下一步权限放大、全量可映射才发布、
   重传幂等、并发/陈旧快照拒绝混用、并发唯一发布、崩溃恢复；
2. 构建检查：全部模块字节编译；
3. API/HTTP 冒烟：真实服务进程上的健康检查、冻结/发布、409 陈旧快照、
   杀进程重开恢复，并对 Compose 内在线 `app` 容器做网络探测。

无 Docker 时可在本机直接运行同一套检查：

```bash
sh verify/run_checks.sh
```

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/healthz` | 健康状态 |
| POST | `/api/verdicts/freeze` | 冻结并裁决（幂等键 `migration_id`） |
| POST | `/api/verdicts/{id}/publish` | 条件发布（仅全部会话可映射） |
| GET | `/api/verdicts/{id}` | 取回裁决 |
| GET | `/api/verdicts` | 裁决列表 |

规程示例：

```json
{
  "name": "isolation-v4",
  "states": {
    "idle":  {"output": "READY", "transitions": {"arm": "armed"}},
    "armed": {"output": "ARMED", "transitions": {"fire": "done", "disarm": "idle"}},
    "done":  {"output": "DONE",  "transitions": {"reset": "idle"}}
  }
}
```

实现仅依赖 Python 3.11 标准库。
